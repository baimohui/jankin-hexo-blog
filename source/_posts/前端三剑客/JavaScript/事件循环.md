事件循环（Event Loop）是 JavaScript 异步编程的核心机制，理解它是成为一名优秀前端工程师的必备技能。本文将从基础概念到浏览器和 Node.js 的实现，全面讲解事件循环。<!-- more -->

---

## 一、为什么需要事件循环？

### 1.1 JavaScript 是单线程的

JavaScript 从诞生之日起就是单线程的。为什么？

**原因：DOM 操作的互斥性**

假设 JavaScript 是多线程的：
- 线程 A 把 DOM 元素的颜色改成红色
- 线程 B 把同一个 DOM 元素的颜色改成蓝色
- 此时浏览器该听谁的？

为了避免这种复杂的同步问题，JavaScript 选择了单线程。

**但单线程会带来问题：**

```js
// 假设这是一个耗时 3 秒的计算
function heavyTask() {
  let sum = 0;
  for (let i = 0; i < 1000000000; i++) {
    sum += i;
  }
  return sum;
}

console.log('开始');
heavyTask();  // 这里会阻塞 3 秒！
console.log('结束');  // 3 秒后才会执行
```

在 `heavyTask` 执行期间：
- 页面无法响应点击
- 动画会卡顿
- 用户体验很差

**这就是事件循环要解决的问题：让单线程的 JavaScript 也能高效处理异步操作。**

## 二、核心概念

### 2.1 执行栈（Call Stack）

执行栈是一个**后进先出（LIFO）**的数据结构，用来存储当前正在执行的函数。

```js
function a() {
  console.log('a');
}

function b() {
  a();
  console.log('b');
}

function c() {
  b();
  console.log('c');
}

c();
```

**执行过程：**
```
1. c() 入栈
   [c]

2. c 调用 b()，b 入栈
   [c, b]

3. b 调用 a()，a 入栈
   [c, b, a]

4. a 执行完，出栈
   [c, b]

5. b 执行完，出栈
   [c]

6. c 执行完，出栈
   []
```

---

### 2.2 任务队列（Task Queue）

当异步任务完成时，它们不会直接进入执行栈，而是先进入**任务队列**。

任务队列分为两类：
1. **宏任务（Macro Task / Task）**
2. **微任务（Micro Task / Job）**

---

### 2.3 宏任务 vs 微任务

| 类型 | 包含 | 说明 |
|------|------|------|
| **宏任务** | `setTimeout` / `setInterval` | 定时器 |
| | `setImmediate`（Node.js）| 立即执行 |
| | I/O 操作 | 文件读写、网络请求等 |
| | UI 渲染（浏览器）| 页面重绘 |
| | `requestAnimationFrame`（浏览器）| 动画帧 |
| **微任务** | `Promise.then/catch/finally` | Promise 回调 |
| | `async/await` | 底层是 Promise |
| | `process.nextTick`（Node.js）| Node 特有 |
| | `MutationObserver`（浏览器）| DOM 变化监听 |
| | `queueMicrotask()` | 手动创建微任务 |

## 三、浏览器中的事件循环

### 3.1 事件循环的执行流程

**一句话总结：一个宏任务，一批微任务。**

```
┌─────────────────────────────────────────────────────────────┐
│                        事件循环                              │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  1. 从宏任务队列中取出一个任务执行                            │
│     │                                                        │
│     ↓                                                        │
│  2. 执行完这个宏任务后，清空微任务队列                         │
│     │  (微任务执行过程中产生的新微任务，也会在本轮执行)        │
│     ↓                                                        │
│  3. 如果需要，执行 UI 渲染                                    │
│     │                                                        │
│     ↓                                                        │
│  4. 回到第 1 步，继续下一个宏任务                             │
│                                                               │
└─────────────────────────────────────────────────────────────┘
```

**关键点：**
- 每次只执行**一个**宏任务
- 执行完这个宏任务后，要把所有微任务都执行完
- 微任务执行过程中产生的新微任务，也会在当前这一轮执行

---

### 3.2 经典例题解析

#### 例题 1：基础版

```js
console.log('1');

setTimeout(() => {
  console.log('2');
}, 0);

Promise.resolve().then(() => {
  console.log('3');
});

console.log('4');
```

**输出结果：**
```
1
4
3
2
```

**执行过程详解：**

| 步骤 | 执行栈 | 宏任务队列 | 微任务队列 | 输出 |
|------|--------|-----------|-----------|------|
| 1 | 执行 `console.log('1')` | [] | [] | 1 |
| 2 | 执行 `setTimeout`，回调加入宏任务 | [setTimeout] | [] | - |
| 3 | 执行 `Promise.resolve().then`，回调加入微任务 | [setTimeout] | [promise] | - |
| 4 | 执行 `console.log('4')` | [setTimeout] | [promise] | 4 |
| 5 | 同步代码执行完，开始处理微任务 | [setTimeout] | [promise] | - |
| 6 | 取出微任务 `console.log('3')` | [setTimeout] | [] | 3 |
| 7 | 微任务清空，开始处理宏任务 | [] | [] | - |
| 8 | 取出宏任务 `console.log('2')` | [] | [] | 2 |

---

#### 例题 2：async/await 版

```js
async function async1() {
  console.log('async1 start');
  await async2();
  console.log('async1 end');
}

async function async2() {
  console.log('async2');
}

console.log('script start');

async1();

setTimeout(() => {
  console.log('setTimeout');
}, 0);

new Promise((resolve) => {
  console.log('promise');
  resolve();
}).then(() => {
  console.log('promise1');
}).then(() => {
  console.log('promise2');
});

console.log('script end');
```

**输出结果（现代浏览器）：**
```
script start
async1 start
async2
promise
script end
async1 end
promise1
promise2
setTimeout
```

**关键点理解：**
- `async` 函数的返回值是 Promise
- `await` 会暂停执行，让出线程
- `await` 后面的代码会被包装成微任务

---

#### 例题 3：微任务中产生微任务

```js
Promise.resolve().then(() => {
  console.log('1');
  Promise.resolve().then(() => {
    console.log('2');
  });
}).then(() => {
  console.log('3');
});
```

**输出结果：**
```
1
2
3
```

**解释：**
微任务队列中的任务会按顺序执行，即使在执行过程中产生新的微任务，也会在当前这一轮全部执行完。

---

### 3.3 事件循环与 UI 渲染

**UI 渲染的时机：**
在微任务队列清空后，下一个宏任务开始前，浏览器可能会进行 UI 渲染。

```
宏任务 → 微任务 → [UI 渲染] → 宏任务 → ...
```

**例子：**

```js
console.log('开始');

setTimeout(() => {
  console.log('setTimeout');  // 宏任务
}, 0);

Promise.resolve().then(() => {
  console.log('promise');  // 微任务
});

requestAnimationFrame(() => {
  console.log('requestAnimationFrame');  // 渲染前执行
});
```

**输出顺序（可能）：**
```
开始
promise
requestAnimationFrame
setTimeout
```

**注意：** `requestAnimationFrame` 不属于宏任务也不属于微任务，它在渲染阶段执行。

## 四、Node.js 中的事件循环

Node.js 的事件循环比浏览器更复杂，它基于 libuv 库实现。

### 4.1 Node.js 事件循环的 6 个阶段

```
   ┌───────────────────────────┐
┌─>│           timers          │ 执行 setTimeout/setInterval 回调
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │     pending callbacks     │ 执行系统回调（如 TCP 错误）
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
│  │       idle, prepare       │ 内部使用
│  └─────────────┬─────────────┘      ┌───────────────┐
│  ┌─────────────┴─────────────┐      │   incoming:   │
│  │           poll            │<─────┤  connections, │ 轮询 I/O 事件
│  └─────────────┬─────────────┘      │   data, etc.  │
│  ┌─────────────┴─────────────┐      └───────────────┘
│  │           check           │ 执行 setImmediate 回调
│  └─────────────┬─────────────┘
│  ┌─────────────┴─────────────┐
└──┤      close callbacks      │ 执行关闭回调，如 socket.on('close')
   └───────────────────────────┘
```

**三个核心阶段：**

1. **timers**：执行 `setTimeout`、`setInterval` 回调
2. **poll**：轮询 I/O 事件，是最复杂的阶段
3. **check**：执行 `setImmediate` 回调

---

### 4.2 Node.js 事件循环的执行流程

**Node.js 11+ 的行为（与浏览器一致）：**
> 每个宏任务执行完后，立即执行对应的微任务队列。

**完整流程：**
1. 进入 timers 阶段
2. 执行一个 timer 回调
3. 执行所有微任务（process.nextTick → Promise.then）
4. 执行下一个 timer 回调（如果有）
5. 进入 pending callbacks 阶段
6. 执行一个 I/O 回调
7. 执行所有微任务
8. 进入 poll 阶段
9. ...

---

### 4.3 process.nextTick

`process.nextTick` 是 Node.js 特有的，它比 Promise.then 优先级更高。

```js
process.nextTick(() => {
  console.log('nextTick');
});

Promise.resolve().then(() => {
  console.log('promise');
});

console.log('sync');
```

**输出：**
```
sync
nextTick
promise
```

**注意：** `process.nextTick` 不属于宏任务也不属于微任务，它在每个阶段切换前执行。

---

### 4.4 setTimeout vs setImmediate

这是一个经典面试题。

```js
setTimeout(() => {
  console.log('setTimeout');
}, 0);

setImmediate(() => {
  console.log('setImmediate');
});
```

**输出顺序不确定！**

**原因：**
- `setTimeout(fn, 0)` 实际上是 `setTimeout(fn, 1)`
- 如果事件循环刚好进入 poll 阶段，setImmediate 会先执行
- 如果事件循环在 timers 阶段，setTimeout 可能先执行

**但在 I/O 回调中是确定的：**

```js
const fs = require('fs');

fs.readFile(__filename, () => {
  setTimeout(() => {
    console.log('setTimeout');
  }, 0);

  setImmediate(() => {
    console.log('setImmediate');
  });
});
```

**输出：**
```
setImmediate
setTimeout
```

**原因：** I/O 回调在 poll 阶段执行，执行完后进入 check 阶段，所以 setImmediate 先执行。

## 五、浏览器 vs Node.js 事件循环对比

| 特性 | 浏览器 | Node.js（11+）|
|------|--------|--------------|
| 宏任务 | setTimeout, setInterval, requestAnimationFrame, I/O | setTimeout, setInterval, setImmediate, I/O |
| 微任务 | Promise.then, async/await, MutationObserver | Promise.then, async/await, process.nextTick |
| 微任务执行时机 | 每个宏任务后 | 每个宏任务后（与浏览器一致）|
| UI 渲染 | 有 | 无 |
| 阶段划分 | 简单 | 6 个阶段 |

## 六、常见面试题

### 面试题 1：什么是事件循环？

**回答要点：**
1. JavaScript 是单线程的
2. 事件循环让单线程的 JS 能处理异步操作
3. 执行栈 + 任务队列（宏任务 + 微任务）
4. 执行规则：一个宏任务，一批微任务

---

### 面试题 2：宏任务和微任务的区别？

**回答要点：**
1. 宏任务：setTimeout, setInterval, I/O 等
2. 微任务：Promise.then, async/await 等
3. 微任务优先级更高
4. 一个宏任务执行完，要清空所有微任务

---

### 面试题 3：代码输出题

```js
console.log('1');

setTimeout(() => {
  console.log('2');
  Promise.resolve().then(() => {
    console.log('3');
  });
}, 0);

Promise.resolve().then(() => {
  console.log('4');
  setTimeout(() => {
    console.log('5');
  }, 0);
});

console.log('6');
```

**输出：**
```
1
6
4
2
3
5
```

## 七、最佳实践

### 7.1 避免阻塞主线程

```js
// ❌ 不好的做法：长时间计算阻塞主线程
function badFibonacci(n) {
  if (n <= 1) return n;
  return badFibonacci(n - 1) + badFibonacci(n - 2);
}

// ✅ 好的做法：分批处理或使用 Web Worker
function goodFibonacci(n) {
  if (n <= 1) return Promise.resolve(n);
  return Promise.all([
    goodFibonacci(n - 1),
    goodFibonacci(n - 2)
  ]).then(([a, b]) => a + b);
}
```

### 7.2 合理使用微任务

```js
// ✅ 使用 queueMicrotask 优化
function doSomethingAsync() {
  if (cache.has(data)) {
    queueMicrotask(() => callback(cache.get(data)));
  } else {
    fetch(data).then(callback);
  }
}
```

## 八、总结

### 8.1 核心知识点

1. **为什么是单线程**：DOM 操作的互斥性
2. **执行栈**：后进先出，存储正在执行的函数
3. **任务队列**：宏任务 + 微任务
4. **执行规则**：
   - 一个宏任务
   - 清空所有微任务（包括新产生的）
   - （可能）UI 渲染
   - 循环

### 8.2 记忆口诀

**浏览器：**
> 先同步，再异步；先微任务，再宏任务。

**Node.js 11+：**
> 和浏览器一致，一个宏任务，一批微任务。

事件循环是 JavaScript 的精髓，理解它能让你写出更高效、更优雅的异步代码！
