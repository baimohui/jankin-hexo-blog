## 一、小程序是什么

小程序是一种**无需下载安装即可使用**的轻量级应用，运行在宿主 App 提供的运行时环境中。用户通过扫码、搜索、分享等方式即可打开，用完即走。<!--more-->

### 小程序的本质

```text
小程序不是 H5（纯 Web 页面），也不是原生 App。

它是介于两者之间的 Hybrid 方案：
  ├── 渲染层：使用 WebView 或自研渲染引擎
  ├── 逻辑层：独立 JS 引擎（JSCore/V8），与渲染层隔离
  ├── 原生能力：通过 JSBridge 调用系统 API（蓝牙、GPS、支付）
  └── 离线缓存：支持本地存储和预加载

因此小程序既有 H5 的快速迭代能力，又接近原生的体验。
```

## 二、主要小程序平台

### 微信小程序（2017）

市场占有率最高，用户基数最大（月活超 9 亿）。

```text
├── 开发语言：WXML + WXSS + JS/TS
├── 运行环境：iOS（JSCore）+ Android（V8 定制版）
├── 发布审核：1-7 天（首次较严，后续更新较快）
├── 包大小：主包 2MB，总包 20MB（分包后）
├── 支付：微信支付（必须开通）
└── 特有能力：
    ├── 微信登录（wx.login + code2session）
    ├── 微信支付（wx.requestPayment）
    ├── 分享到聊天 / 朋友圈
    ├── 公众号 / 服务号 / 企业微信互通
    └── 云开发（云函数 + 云数据库 + 云存储）
```

### 支付宝小程序（2017）

依托支付宝的电商和金融场景。

```text
├── 开发语言：AXML + ACSS + JS
├── 与微信差异：语法相似，API 命名不同（my.request → wx.request）
├── 优势场景：支付、信用、保险、生活缴费
├── 启动速度：比微信略快（支付宝内核优化）
└── 特有能力：
    ├── 支付宝支付（my.tradePay）
    ├── 芝麻信用
    ├── 花呗 / 借呗
    └── 蚂蚁森林 / 蚂蚁庄园打通
```

### 百度智能小程序（2018）

依托百度搜索流量分发的优势。

```text
├── 开发语言：SWAN + CSS + JS
├── 最大特点：**搜索流量分发**——小程序内容可以被百度搜索收录
├── 优势场景：内容资讯、工具查询、本地生活
├── 自有框架：Swan.js（兼容 React 语法）
└── 特有能力：
    ├── 百度搜索直达
    ├── 百度 AI 开放平台（语音、图像识别）
    └── 百家号联动
```

### 字节跳动/抖音小程序（2019）

依托抖音的娱乐和电商场景。

```text
├── 开发语言：TTML + TTSS + JS
├── 最大特点：**流量巨大**——抖音日活 7 亿+
├── 优势场景：短视频带货、直播电商、小游戏
├── 特有能力：
    ├── 抖音短视频挂载
    ├── 抖音直播带货
    ├── 头条 / 西瓜视频打通
    └── 抖音电商（抖音小店）
```

### 快手小程序（2020）

主打社交电商和直播场景。

```text
├── 与微信差异：语法兼容微信（可直接迁移部分代码）
├── 优势场景：直播电商、同城服务
└── 特点：社区氛围强，低线城市渗透率高
```

### 华为快应用（2018）

不同于其他小程序，快应用基于**手机系统级**运行，无需安装 App。

```text
├── 运行环境：手机系统直接支持（无需打开微信/支付宝）
├── 开发语言：JS + 自定义标签
├── 优势场景：轻量工具、信息查询
├── 特点：
    ├── 桌面级入口（从手机桌面直接打开）
    ├── 无需安装宿主 App
    ├── 硬件厂商支持（华为、小米、OPPO、vivo 联合推出）
    └── 性能最好（系统级集成）
```

## 三、跨端框架

由于每个平台的语法和 API 不同，一套代码无法直接运行在多个平台。跨端框架解决了这个问题：

### Taro（京东）

```jsx
// 一套 React 代码，编译到多端
function Index() {
  return (
    <View className="index">
      <Text>Hello Taro</Text>
      <Button onClick={handleClick}>点击</Button>
    </View>
  );
}
```

```text
├── 语法：React（JSX）
├── 支持编译到：微信 / 支付宝 / 百度 / 字节 / QQ / 快手 / H5 / RN
├── 特点：编译时 + 运行时双引擎
├── 知名用户：京东、58同城、安居客
└── 版本：Taro 3 全面支持 Hooks
```

### uni-app（DCloud）

```vue
<template>
  <view class="container">
    <text>{{ message }}</text>
  </view>
</template>

<script>
export default {
  data() { return { message: 'Hello uni-app' } },
  onLoad() { uni.request({ url: '/api/data' }) },
}
</script>
```

```text
├── 语法：Vue
├── 支持编译到：微信 / 支付宝 / 百度 / 字节 / QQ / 快手 / H5 / App（iOS+Android）
├── 特点：发行早、用户量大、插件市场丰富
├── 知名用户：阿里、快手、网易
└── 版本：uni-app 3（Vue 3 + Vite）
```

### 跨端框架对比

| 框架 | 语法 | 支持端数 | 性能 | 脚手架 | 社区 |
|------|------|---------|------|--------|------|
| Taro | React | 8 | 编译时优化好 | CLI 完善 | 京东主导、GitHub 34k stars |
| uni-app | Vue | 10 | 运行时适配 | HBuilderX IDE | DCloud、插件最多 |
| kbone | React/Vue | 1(主要微信)+H5 | 接近原生 | Webpack | 腾讯出品 |
| mpvue | Vue | 2(微信+H5) | 中等 | CLI | 已停止维护，被 uni-app 取代 |
| chameleon | 自定义 | 5 | 编译时 | CLI | 滴滴出品，维护较少 |

### 跨端框架的原理

```text
├── 编译时方案（Taro 1/2、uni-app）
│   将源码编译为目标平台的模板语言。
│   优点：运行时开销小。
│   缺点：不支持动态组件、JSX 语法受限。

├── 运行时方案（Taro 3、kbone）
│   在目标端模拟 DOM/BOM API，运行完整的 React/Vue 框架。
│   优点：语法不受限、可直接复用 Web 组件。
│   缺点：运行时开销大、性能稍差。

└── 混合方案（Taro Next）
    编译时 + 运行时结合，静态部分编译、动态部分运行时。
```

## 四、小程序生态的核心角色

### 小程序开发者

```text
├── 个人开发者：可以注册个人小程序（部分功能受限）
├── 企业开发者：全功能开放，支持支付
└── 服务商：帮商家开发、代运营小程序
```

### 第三方平台

```text
├── 微信开放平台
├── 支付宝开放平台
├── 小程序云（云开发、云函数）
├── SaaS 建站工具（有赞、微盟）
└── 数据分析工具（阿拉丁、GrowingIO）
```

### 小程序服务商

```text
├── SaaS 建站：有赞（电商）、微盟（零售）、上线了（通用）
├── 数据分析：阿拉丁（小程序统计）、GrowingIO（用户行为）
├── 客服工具：网易七鱼、智齿
└── 广告投放：微信广告、腾讯广告
```

## 五、小程序的商业模式

```text
├── 电商变现
│   有赞 / 微盟提供 SaaS 工具，商家开店卖货。
│   抖音小店 + 直播带货 = 2025 年万亿 GMV。

├── 广告变现
│   内容类小程序（资讯、视频）通过广告联盟变现。
│   微信广告、百度广告。

├── 服务变现
│   工具类小程序（记账、打卡）通过会员订阅收费。

├── 游戏变现
│   微信小游戏通过道具内购和广告分成。
│   微信小游戏月活超 4 亿。

└── 线下引流
    扫码点餐、排队取号、停车场缴费——线下流量线上化。
```

## 六、小程序与 H5 的选型

```text
选择小程序：
  ├── 需要微信生态（支付、分享、登录）
  ├── 需要原生能力（蓝牙、NFC、GPS）
  ├── 需要更好的用户体验（接近原生）
  ├── 低频使用场景（用完即走）
  └── 目标用户主要是移动端

选择 H5：
  ├── 需要搜索引擎收录（SEO）
  ├── 需要快速迭代、无需审核
  ├── 需要跨平台（PC / 移动 / Pad）
  ├── 需要复用现有 Web 技术栈
  └── 包大小超过小程序限制

两者共存：
  许多产品同时有小程序（获客）+ H5（承接深度操作）。
  例如：电商小程序（浏览购买）→ H5 帮助中心 / 售后服务。
```

## 七、小程序的未来趋势

```text
├── 跨端统一
│   跨端框架成熟，一次开发多端部署成为标准实践。
│   微信、支付宝、抖音的 API 差距在缩小。

├── 云原生
│   微信云开发、支付宝云开发让小程序无需自建后端。
│   云函数 + 云数据库 + 云存储 = 全栈小程序。

├── AI 结合
│   微信 AI 助手、百度 AI 开放平台、字节豆包模型。
│   小程序内嵌 AI 功能成为增长点。

├── 小程序互联
│   微信小程序 → 公众号 → 企业微信 → 视频号，全链路打通。
│   抖音小程序 → 直播 → 电商，转化路径最短。

└── 硬件入口
    华为快应用从手机桌面级入口扩展到车机、手表。
    小程序不再局限于手机。
```
