## 新文档结构

### 一、开篇：一个故事串联全局（新增）

- 你的工牌 → Token / Session
- 不同分公司的工牌互认 → SSO

### 二、前端鉴权概览（新增）
**核心问题**：HTTP 无状态，前后端如何互信？
一张整体关系图 + 表格横向对比四种方式的"是什么-优缺点-适用场景"：
| 方式 | 状态存放 | 是否跨域 | CSRF防护 | 适用场景 |
|------|----------|----------|----------|----------|
| Cookie+Session | 服务端 | 否 | 需防护 | 传统 web |
| Token(JWT) | 客户端 | 是 | 天然防御 | SPA/移动端 |
| OAuth 2.0 | 第三方 | 是 | - | 第三方登录 |
| SSO | 统一认证中心 | 跨站点 | - | 多系统打通 |

### 三、从 Cookie 说起（原第四节提升到前面）
保留核心知识点但重新组织：
- **Cookie 的本质**：服务端塞给浏览器的小纸条
- **Cookie 的属性**（精简为面试高频点）：Domain/Path/Expires/Max-Age/Secure/HttpOnly/SameSite
  - **重点补充 SameSite**（Lax/Strict/None），这是现代 CSRF 防御核心
- **Cookie 的限制**：4KB、同源、每次请求自动携带
- **Cookie 的安全使用**：HttpOnly + Secure + SameSite 组合拳
- **Cookie 禁用问题**：精简保留，删除 Flash 相关过时内容

### 四、localStorage & sessionStorage（原第四节改造）
改为对比视角，与 Cookie 对照讲解：
- **三者的面试高频对比表**：生命周期、大小、HTTP携带、跨域、安全性
- **Storage 的安全问题**：XSS 可直接读取，不能存敏感信息
- **Storage 的常见用途**：存 token、存用户偏好、缓存数据
- **面试常问**：localStorage 跨标签页通信、storage 事件

### 五、Cookie + Session 认证（原第三节改造）
讲清楚"经典登录"的完整链路，配合流程图：
- **Session 工作原理**：服务端开辟空间 → Set-Cookie: JSESSIONID → 后续请求携带
- **Session 的分布式问题**：粘性会话 vs 集中式 Session（Redis）
- **Session vs Token 的本质区别**："服务端有状态" vs "客户端有状态"
- **面试常问**：Session 在集群下怎么解决？Session 占用服务器内存怎么办？

### 六、Token 认证（原第一节）
核心内容重构，突出重点：
- **Token 的诞生动机**：解决 Cookie+Session 的什么问题？
- **Token vs Session 对比**：面试高频
- **Access Token + Refresh Token 机制**：为什么需要两个？
- **无痛刷新 Token 实战**：保留 axios 拦截器代码，但要现代化
  - 更清晰的注释
  - 补充 Promise 队列的通俗解释
- **Token 存储位置选择**：localStorage vs cookie vs memory
  - 展开讲安全权衡，这是面试常考

### 七、JWT（原第一节子章节）
独立成节，也是面试绝对重点：
- **JWT 是什么**：三段式结构（Header.Payload.Signature）
- **JWT 工作原理通俗解释**：类比"防伪标签"——可验证、不可篡改
- **JWT 签名算法**：HS256 vs RS256 的选择
- **JWT 的典型问题**（面试重点）：
  - 如何注销？→ 黑名单 / 短有效期
  - 如何防止被盗？→ HTTPS + 短有效期 + 指纹
  - 如何防重放？→ timestamp + nonce
  - JWT 无状态真的好吗？→ tradeoff 讨论
  - "none" 算法攻击、算法混淆攻击
- **JWT 不适合的场景**

### 八、OAuth 2.0 与 SSO（原第二节改造）
从面试角度重新组织：
- **SSO 的核心思想**：一次登录，全网通行
- **OAuth 2.0 四种授权模式**（重点 Authorization Code + PKCE）：
  - 用"借书证"的类比讲清楚四个角色
  - 授权码流程逐步拆解
  - 为什么移动端要 PKCE？
- **OAuth 2.0 vs SAML 2.0**：简化对比，SAML 主要提历史背景
- **OAuth 2.0 vs OpenID Connect (OIDC)**：新增！OIDC 在 OAuth 之上加身份层
- **SSO 的实现分类**：同域 SSO（共享 Cookie） vs 跨域 SSO（CAS/OAuth）
